# C library for other UIs (roadmap item 4)

Ship macmon's rootless metrics as `libmacmon.dylib` / `libmacmon.a` with a C header and a
`CMacmon.xcframework`, so Swift, Python, Go or C apps sample them without running `macmon pipe`.
Exposed: power (CPU, GPU, ANE, RAM, GPU SRAM, system), temperatures, CPU tiers with per-core
frequency and scaled/active ratios, GPU frequency and ratios, memory and swap, fans, SoC info. Not
exposed: processes, `debug`, `find-clpc`, `stress`, `serve`. Bindings stay outside the repository.

## Starting point

- **#59** (draft, homm): workspace split, `ffi.rs` (520 lines), hand-written `macmon.h` (139 lines)
  of caller-allocated structs, `module.modulemap`, `make xcframework`. Its model (`cpu_domains`,
  `power.package/board/battery/dc_in`, SMC-only temperatures) is not on `main`, which has
  `cpu_tiers`, scaled + active ratios, a baseline between samples, fans, the HID fallback and the
  `app` feature instead. Its lifecycle, status codes and packaging still fit; its `PANIC` status
  never fires under the release `panic = "abort"`.
- **[homm/macmon-bindings](https://github.com/homm/macmon-bindings)**: Python (cffi, parses the
  header) and Swift (SPM `binaryTarget(url:checksum:)`) over #59's v0.7.3 `CMacmon.xcframework`
  (dylib + headers, arm64, macOS 11) from homm's fork; they copy the structs into their own types.
  They need an upstream `CMacmon.xcframework-vX.Y.Z.zip`, stable symbols and a model that doesn't
  force a rewrite each release.

## Decision for the owner: struct API (A) or JSON API (B)

**A. Plain structs**, for `main`'s model:

```c
typedef struct { uint32_t die_id, core_id, freq_mhz; float scaled_ratio, active_ratio; } macmon_core_t;
typedef struct { const char *label; uint32_t freq_mhz; float scaled_ratio, active_ratio;
                 size_t cores_len; const macmon_core_t *cores; } macmon_cpu_tier_t;
typedef struct { const char *name; uint32_t rpm, max_rpm; /* 0 = unknown */ } macmon_fan_t;
typedef struct {
  uint32_t struct_size;              /* set by the library; fields are only appended */
  float cpu_temp_avg, gpu_temp_avg;  /* NAN when unavailable */
  uint64_t ram_total, ram_usage, swap_total, swap_usage;
  float cpu_scaled_ratio, cpu_active_ratio; size_t cpu_tiers_len; const macmon_cpu_tier_t *cpu_tiers;
  uint32_t gpu_freq_mhz; float gpu_scaled_ratio, gpu_active_ratio;
  float cpu_power, gpu_power, ane_power, all_power, sys_power, ram_power, gpu_ram_power;
  size_t fans_len; const macmon_fan_t *fans;
} macmon_metrics_t;
macmon_status_t macmon_sampler_next(macmon_sampler_t *s, uint32_t interval_ms, macmon_metrics_t **out);
void macmon_metrics_free(macmon_metrics_t *m);  /* macmon_soc_info_t likewise */
```

ABI: library-allocated (with #59's caller-allocated structs an appended field overruns an old
caller's struct), `struct_size` says which fields exist, append-only; a removed or retyped field
bumps `MACMON_ABI_VERSION`. Cost: ~400 Rust lines (conversion, nested frees, tests) + ~130 header
lines, over the ~200-line rule; every new metric touches Rust, the C struct, the header and each
binding.

**B. JSON** of `Metrics` / `SocInfo` through `serde_json` (already a library dependency,
`Serialize` already derived):

```c
#define MACMON_ABI_VERSION 1
typedef enum macmon_status_t { MACMON_STATUS_OK = 0, MACMON_STATUS_INVALID_ARGUMENT = 1,
  MACMON_STATUS_INIT_FAILED = 2, MACMON_STATUS_SAMPLE_FAILED = 3, MACMON_STATUS_PANIC = 4 } macmon_status_t;
typedef struct macmon_sampler macmon_sampler_t;
uint32_t macmon_abi_version(void);     /* MACMON_ABI_VERSION the library was built with */
const char *macmon_version(void);      /* "0.10.0", static */
macmon_status_t macmon_sampler_new(macmon_sampler_t **out_sampler);
void macmon_sampler_free(macmon_sampler_t *sampler);  /* NULL: no-op */
/* Blocks until interval_ms after the previous sample; 0 returns at once with the interval since
   the previous call (or macmon_sampler_new). *out_json: a Metrics object. */
macmon_status_t macmon_sampler_next_json(macmon_sampler_t *sampler, uint32_t interval_ms, char **out_json);
macmon_status_t macmon_get_soc_info_json(char **out_json);  /* a SocInfo object */
void macmon_string_free(char *json);                        /* NULL: no-op */
const char *macmon_last_error_message(void);  /* this thread's last error, NULL after success */
```

Python: `ctypes` + `json.loads`, no cffi build or header parsing; Swift: `Codable` with
`.convertFromSnakeCase` (unknown keys ignored); Go: cgo + `encoding/json`. Stability: symbols only
grow; the schema is the documented `pipe` one, so new metrics reach every binding without an ABI
change, removals follow Rust deprecations (`ecpu_*`/`pcpu_*` since 0.10.0). Cost: ~130 Rust +
~50 header lines; a few KB of JSON per sample, microseconds against a 100+ ms interval.

**C. Both**: A's cost on top of B; only if a consumer measures JSON as a bottleneck.

**Recommendation: B.** The C ABI stays fixed while the model still moves (tiers in 0.10, macOS 27
power sources), it fits one small PR, and it is the least change for homm: lifecycle, status codes,
error message and the `CMacmon` module keep #59's names; each wrapper's struct copying becomes a
JSON decode. With A or B the bindings move to `main`'s model anyway.

## Behavior (B)

- `next_json` returns `serde_json::to_string(&Metrics)`: the readme's `pipe` fields without
  `timestamp` and the v0.7 aliases `pipe` adds (`cpu_usage_pct`, `ecpu_usage`, `pcpu_usage`,
  `gpu_usage`); unavailable temperatures are `null`. SoC info equals `pipe --soc-info`'s `soc`.
- `macmon_sampler_new` primes the baseline (one discarded `get_metrics(0)`), so the first sample
  covers a real interval, as the bindings expect with `interval_ms = 0`.
- Every function rejects NULL arguments (`INVALID_ARGUMENT`), sets `*out` to NULL first, maps
  `Sampler::new` errors to `INIT_FAILED` and `get_metrics` errors to `SAMPLE_FAILED`, and catches
  panics (`PANIC`). The message is a thread-local `CString`, valid until the next call on that
  thread. Calls on one sampler must not overlap.

## Build decisions

- **Separate crate `capi/`** (`macmon-capi`, `publish = false`, `[lib] name = "macmon"`,
  `crate-type = ["cdylib", "staticlib"]`, `doc = false`, depends on `macmon` with
  `default-features = false`); the root stays the `macmon` package with `[workspace] members =
  ["capi"]`, so `cargo build` / `cargo install` build only `macmon`, `include` keeps `capi/` off
  crates.io and the dylib links no CLI dependencies. Rejected: `crate-type` on the main crate
  (every `cargo install` builds both) and a feature (crate types can't be feature-gated). Checked
  in a toy workspace: the same lib name in both crates doesn't collide.
- **Profile `capi`** (`inherits = "release"`, `panic = "unwind"`): the TUI keeps aborting, the
  library returns `PANIC` instead of killing the host app.
- **Hand-written** `capi/include/macmon.h` + `module.modulemap` (`module CMacmon`): eight
  functions don't justify cbindgen; the C smoke test checks them against the dylib.
- **install_name** `@rpath/libmacmon.dylib` from `capi/build.rs` (`cargo:rustc-cdylib-link-arg`);
  without it the toy dylib carried its absolute `target/` path. arm64 only, Rust's default macOS
  11 deployment target, no `lipo`.
- **Artifacts** in `out/` (gitignored): `libmacmon-vX.Y.Z.tar.gz` (`include/`, `lib/libmacmon.dylib`,
  `lib/libmacmon.a`, `LICENSE`) and `CMacmon.xcframework-vX.Y.Z.zip` (`xcodebuild
  -create-xcframework -library … -headers include`, `ditto -c -k --keepParent`, homm's layout).
