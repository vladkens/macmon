# C library for other UIs (roadmap item 4)

Ship macmon's rootless metrics as `libmacmon.dylib` with a C header and a `CMacmon.xcframework`, so
Swift, Python, Go or C apps sample them without running `macmon pipe`. Exposed: power (CPU, GPU,
ANE, RAM, GPU SRAM, system), temperatures, CPU tiers with per-core frequency and scaled/active
ratios, GPU frequency and ratios, memory and swap, fans, SoC info. Not exposed: processes, `debug`,
`find-clpc`, `stress`, `serve`. Bindings stay outside the repository.

## Starting point

- **#59** (draft, homm): workspace split, `ffi.rs` (520 lines), hand-written `macmon.h` (139 lines)
  of caller-allocated structs, `module.modulemap`, `make xcframework`. Its model (`cpu_domains`,
  `power.package/board/battery/dc_in`, SMC-only temperatures) is not on `main`, which has
  `cpu_tiers`, scaled + active ratios, a baseline between samples, fans, the HID fallback and the
  `app` feature instead. Its lifecycle, status codes and packaging still fit; its `PANIC` status
  never fires under the release `panic = "abort"`.
- **[homm/macmon-bindings](https://github.com/homm/macmon-bindings)**: Python (cffi, parses the
  header) and Swift (SPM `binaryTarget(url:checksum:)`) over #59's v0.7.3 `CMacmon.xcframework`
  (dylib + headers, arm64, macOS 11) from homm's fork; they copy the structs into their own types.
  They need an upstream `CMacmon.xcframework-vX.Y.Z.zip`, stable symbols and a model that doesn't
  force a rewrite each release.

## Decision 1: struct API (A) or JSON API (B)

**A. Plain structs**, for `main`'s model:

```c
typedef struct { uint32_t die_id, core_id, freq_mhz; float scaled_ratio, active_ratio; } macmon_core_t;
typedef struct { const char *label; uint32_t freq_mhz; float scaled_ratio, active_ratio;
                 size_t cores_len; const macmon_core_t *cores; } macmon_cpu_tier_t;
typedef struct { const char *name; uint32_t rpm, max_rpm; /* 0 = unknown */ } macmon_fan_t;
typedef struct {
  uint32_t struct_size;              /* set by the library; fields are only appended */
  float cpu_temp_avg, gpu_temp_avg;  /* NAN when unavailable */
  uint64_t ram_total, ram_usage, swap_total, swap_usage;
  float cpu_scaled_ratio, cpu_active_ratio; size_t cpu_tiers_len; const macmon_cpu_tier_t *cpu_tiers;
  uint32_t gpu_freq_mhz; float gpu_scaled_ratio, gpu_active_ratio;
  float cpu_power, gpu_power, ane_power, all_power, sys_power, ram_power, gpu_ram_power;
  size_t fans_len; const macmon_fan_t *fans;
} macmon_metrics_t;
macmon_status_t macmon_sampler_next(macmon_sampler_t *s, uint32_t interval_ms, macmon_metrics_t **out);
void macmon_metrics_free(macmon_metrics_t *m);  /* macmon_soc_info_t likewise */
```

ABI: library-allocated (with #59's caller-allocated structs an appended field overruns an old
caller's struct), `struct_size` says which fields exist, append-only; a removed or retyped field
bumps `MACMON_ABI_VERSION`. Cost: ~400 Rust lines (conversion, nested frees, tests) + ~130 header
lines, over the ~200-line rule; every new metric touches Rust, the C struct, the header and each
binding.

**B. JSON** of `Metrics` / `SocInfo` through `serde_json` (already a library dependency,
`Serialize` already derived):

```c
#define MACMON_ABI_VERSION 1
typedef int32_t macmon_status_t;
enum { MACMON_STATUS_OK = 0, MACMON_STATUS_INVALID_ARGUMENT = 1, MACMON_STATUS_INIT_FAILED = 2,
       MACMON_STATUS_SAMPLE_FAILED = 3, MACMON_STATUS_PANIC = 4 };
/* A sampler may be used from any thread, one call at a time, never concurrently. */
typedef struct macmon_sampler macmon_sampler_t;
uint32_t macmon_abi_version(void);     /* MACMON_ABI_VERSION the library was built with */
const char *macmon_version(void);      /* macmon's version, "0.10.0"; static */
macmon_status_t macmon_sampler_new(macmon_sampler_t **out_sampler);
void macmon_sampler_free(macmon_sampler_t *sampler);  /* NULL: no-op */
/* Blocks until interval_ms after the previous sample; 0 returns at once with the interval since
   the previous call (or macmon_sampler_new). *out_json: a Metrics object. */
macmon_status_t macmon_sampler_next_json(macmon_sampler_t *sampler, uint32_t interval_ms, char **out_json);
macmon_status_t macmon_get_soc_info_json(char **out_json);  /* a SocInfo object */
void macmon_string_free(char *json);                        /* NULL: no-op */
const char *macmon_last_error_message(void);  /* this thread's last error, NULL after success */
```

Python: `ctypes` + `json.loads`, no cffi build or header parsing; Swift: `Codable` with
`.convertFromSnakeCase` (unknown keys ignored); Go: cgo + `encoding/json`. Stability: symbols and
JSON keys are only added; removing or retyping either bumps `MACMON_ABI_VERSION`. Cost: ~130 Rust +
~50 header lines; a few KB of JSON per sample, microseconds against a 100+ ms interval.

**C. Both**: A's cost on top of B; only if a consumer measures JSON as a bottleneck.

**Recommendation: B.** The C ABI stays fixed while the model still moves (tiers in 0.10, macOS 27
power sources), it fits one small PR, and it is the least change for homm: lifecycle, status codes,
error message and the `CMacmon` module keep #59's names (status becomes a plain `int32_t`); each
wrapper's struct copying becomes a JSON decode. With A or B the bindings move to `main`'s model.

## Decision 2: build as a feature (F) or a workspace crate (W)

**F. `capi` feature of the main crate**: `src/capi.rs` behind `#[cfg(feature = "capi")]`, built
with `cargo rustc --lib --profile capi --no-default-features --features capi --crate-type
cdylib,staticlib -- -C link-arg=-Wl,-install_name,@rpath/libmacmon.dylib` (`--crate-type` is stable
since 1.64). Checked on a copy of the real crate (M2, Mac14,7): it builds a 0.6 MB dylib with
install name `@rpath/libmacmon.dylib`, only the `#[unsafe(no_mangle)]` symbols exported, and a
clang-compiled caller printed the SoC JSON. Version is `CARGO_PKG_VERSION`, the lockfile, `make
remote`, `--workspace` flags and `loc.py` stay as they are. Cost: a visible `capi` feature and
`src/capi.rs` in the published crate (not built on docs.rs, which uses `no-default-features`).

**W. Workspace crate `capi/`** (`macmon-capi`, `publish = false`, `[lib] name = "macmon"`, depends
on `macmon` with `default-features = false`): keeps FFI out of the published crate (a toy workspace
showed the shared lib name doesn't collide), but needs `[workspace.package] version` with
`version.workspace = true` (root package first so `main.yml`'s version grep still works),
`[workspace.lints]`, `--workspace` in `prepare`/`check`/`test`, `capi` in `make remote`'s rsync, a
`loc.py` part and a `build.rs` for the install name.

**Recommendation: F**: fewer moving parts, no version drift; `cargo install macmon` and the
library build don't enable the feature. Rejected for both: `crate-type` in `Cargo.toml` (every
`cargo install` would build a cdylib and staticlib).

## Behavior

- `next_json` serializes `Metrics` through `serde_json::Value` and drops the keys deprecated since
  0.10.0 (`ecpu_*`/`pcpu_*` in `Metrics`, `metrics.rs`; `ecpu_*`/`pcpu_*` in `SocInfo`,
  `sources.rs`), and adds `"schema"` and `"timestamp_ms"` (SoC info: `"schema"` only). So it
  differs from `pipe`: `timestamp_ms` instead of the RFC 3339 `timestamp`, no v0.7 aliases
  (`cpu_usage_pct`, `ecpu_usage`, `pcpu_usage`, `gpu_usage`), no deprecated keys; unavailable
  temperatures are `null`.
- `macmon_sampler_new` primes the baseline (one discarded `get_metrics(0)`; an error there is
  `INIT_FAILED`), so the first sample covers a real interval, as the bindings expect with
  `interval_ms = 0`.
- Every function rejects NULL arguments (`INVALID_ARGUMENT`), sets `*out` to NULL first, maps
  `get_soc_info` / `Sampler::new` errors to `INIT_FAILED` and `get_metrics` errors to
  `SAMPLE_FAILED`, and catches panics (`PANIC`). After a `PANIC` the sampler is poisoned: later
  calls return `PANIC`, only `free` is valid. The message is a thread-local `CString`, valid until
  the next call on that thread.
- Rust: `pub unsafe extern "C" fn` with `# Safety` docs and explicit `unsafe {}` blocks
  (`unsafe_op_in_unsafe_fn`), `#[unsafe(no_mangle)]` (edition 2024); every function that
  dereferences a pointer argument is `unsafe` (`clippy::not_unsafe_ptr_arg_deref`); the crate's
  lints apply.

## Build and packaging

- **Profile `capi`** (`inherits = "release"`, `panic = "unwind"`): the TUI keeps aborting, the
  library returns `PANIC` instead of killing the host app. Only `--profile capi` artifacts are
  supported: under `abort` `catch_unwind` does nothing.
- **Hand-written** `include/macmon.h` + `include/module.modulemap` (`module CMacmon`): eight
  functions don't justify cbindgen; the C smoke test checks them against the dylib.
- arm64 only, `MACOSX_DEPLOYMENT_TARGET=11.0`, no `lipo`. **Dylib for C, Python and Go; static
  library in the XCFramework**: SwiftPM (Swift 6.4's default build system) adds no rpath for a
  dylib or framework binary target, so `swift run` fails with "Library not loaded: @rpath/…". The
  XCFramework carries `libmacmon.a` (19 MB, 3 MB after `strip -S`), and `module.modulemap` links
  its system libraries (`CoreFoundation`, `IOKit`, `IOReport`, `iconv`, from
  `--print native-static-libs`), so Swift needs no linker flags. Cost: one copy of the Rust std per
  app, which clashes with another Rust staticlib's std in the same binary.
- **Artifacts** in `out/` (gitignored): `libmacmon-vX.Y.Z.tar.gz` (`include/`,
  `lib/libmacmon.dylib`, `LICENSE`), `CMacmon.xcframework-vX.Y.Z.zip` (`xcodebuild
  -create-xcframework -library libmacmon.a -headers include`, `ditto -c -k --keepParent`) and its
  SPM checksum file (`swift package compute-checksum`). The dylib is ad-hoc signed, not notarized:
  the readme says to download with `curl` or run `xattr -dr com.apple.quarantine`.

## Owner's decisions

- API **B** (JSON) and build **F** (a `capi` feature of the main crate).
- The sample JSON carries `"timestamp_ms"`: Unix milliseconds of the sample, from `std` (no chrono
  in the library).
- Versioning: every sample and SoC JSON carries `"schema": 1`, the same number as
  `macmon_abi_version()` / `MACMON_ABI_VERSION`. Keys are only added; removing, renaming or
  retyping a key bumps it. The deprecated `ecpu_*`/`pcpu_*` keys never appear (clean start). The
  readme documents every key and this rule; callers check the version at start.
- A published JSON Schema (`macmon.schema.json` per release, so quicktype etc. can generate Swift /
  Python / Go types) is wanted; generating it with `schemars` is a new dependency and waits for the
  owner's approval, so it is not in tasks 1–3.
