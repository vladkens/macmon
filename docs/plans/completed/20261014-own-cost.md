# macmon's own cost (roadmap item 8)

Measure what `pipe`, `serve` and the TUI cost at 1000 ms and 250 ms, find the hot paths and fix
what is cheap, with output, JSON, Prometheus, the config and the library API unchanged.

## Measurement

- Release builds of `origin/main` and the branch run at the same time, one pair per mode, two
  rounds, so both see the same load (other apps and VMs run on this Mac).
- `self`: CPU seconds per minute of the macmon process (`ps -o time`) over 60 s after a 4 s
  warm-up. `total`: CPU seconds per minute of wall time of macmon and the `ps` processes it
  spawns (`/usr/bin/time`), startup included.
- TUI in tmux at 160×45 with its own `HOME`; the list hidden with `p` (2 s after the start); the
  info overlay on Chrome's main process (560 descriptors). `serve` gets `curl /metrics` every 5 s.
- Energy Impact: `top -stats power` over the same 60 s, Activity Monitor's column; it counts
  macmon only, not its `ps`. Rootless only: no `powermetrics` task energy.
- Profiles: `sample <pid> 10`, per-thread CPU (`ps -M`), and a temporary build with thread CPU
  timers (`CLOCK_THREAD_CPUTIME_ID`) around each step, not committed.

## Findings

CPU per sample on an M2 with about 670 processes, 215 of them of other users:

| Where | Step | CPU |
| --- | --- | --- |
| `ps` child | `ps -A`: setuid, reads every process | 25 ms |
| process thread | libproc 2.2, executable paths 1.9, GPU clients 1.4, `ps` spawn and parse 0.8 | 6.5 ms |
| metrics thread | IOReport sample 1.6, SMC temperatures 0.9 (about 55 keys) | 2.8 ms |
| main thread | info overlay refresh, 560 descriptors | 2.5 ms |
| main thread | a frame; 1 ms with the info overlay | 0.4 ms |

- The `ps` the process list spawns cost twice as much as macmon itself. Its cost grows with every
  process it reads, whatever the columns: `-U <users>` reads only the processes of these real
  users (about 220 here, 9 ms); `-p <pids>` costs more per process than `-A`.
- Processes of the own real user that libproc can't read are setuid ones, mostly the `login` of
  every terminal tab: with the own user, `ps -U` would read all its processes again.
- The TUI drew a frame every 250 ms on a timer on top of the frames of every sample.
- `pipe` and `serve` cost what the TUI's metrics thread does per sample; nothing cheap to cut there.

## Decisions

- `ps` selects the processes libproc can't read: `-U` with the names of their real users
  (`PROC_PIDT_SHORTBSDINFO`, readable for every process), `-p` with those of the own real user
  and of users without a name (`ps -U` refuses unknown users). Same rows as before: checked on
  this Mac, all 217 rows with the same pid, user and command.
- The TUI draws on events only (samples, input, resize): nothing on screen changes on its own.
- Not done, as each changes output or timing, or costs lines for little: temperatures read less
  often than every sample, `ps` every other tick at 250 ms, executable paths only on a new
  executable (rusage UUID), cached rows of the info overlay, one IORegistry call per GPU client.
- Found, not changed: `ps` prints uid -2 (`nobody`) as `-2`, which the row parser rejects, so
  `nobody`'s processes (`dhcp6d`) are missing from the list, before and after.

## Result

CPU seconds per minute, `origin/main` → branch, mean of two rounds; Energy Impact as `top` shows
it. Rounds of the same build differ by up to 40 % at 250 ms (other load on the Mac): the drop of
`total` with the list is larger than that, the differences of `self` at 250 ms are not.

| Mode | self | total, with `ps` | Energy Impact |
| --- | --- | --- | --- |
| `pipe -i 1000` | 0.24 → 0.25 | 0.30 → 0.30 | 0.35 → 0.35 |
| `pipe -i 250` | 0.79 → 0.80 | 0.86 → 0.86 | 1.25 → 1.25 |
| `serve -i 1000` | 0.21 → 0.21 | 0.27 → 0.28 | 0.3 → 0.3 |
| TUI 1000 ms | 1.14 → 0.78 | 3.28 → 1.73 | 1.8 → 1.25 |
| TUI 1000 ms, list hidden | 0.58 → 0.39 | 0.83 → 0.55 | 0.9 → 0.6 |
| TUI 1000 ms, info overlay | 1.11 → 0.97 | 3.32 → 2.01 | 1.75 → 1.55 |
| TUI 250 ms | 3.12 → 2.91 | 10.41 → 6.24 | 5.1 → 4.8 |
| TUI 250 ms, list hidden | 1.38 → 1.15 | 1.90 → 1.46 | 2.25 → 1.85 |
| TUI 250 ms, info overlay | 3.40 → 3.42 | 11.24 → 7.11 | 5.6 → 5.6 |

- With the process list, the TUI and its `ps` cost 37–47 % less CPU: 1.7 s a minute at 1000 ms
  (3 % of a core), 6.2 s at 250 ms. The `ps` child is still the largest part.
- With the list hidden, 0.2 s a minute less: the redraw timer.
- `pipe` and `serve` are unchanged: 0.2–0.3 s a minute at 1000 ms.
- macmon's own POWER in its list: 0.01–0.02 W in both builds (it leaves out `ps`).
