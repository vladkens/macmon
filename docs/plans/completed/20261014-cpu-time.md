# CPU TIME column (roadmap item 5, first column), with two fixes

One PR for release 0.10: a `TIME` column in the process list with the total CPU time of each
process, a scrollbar on the help overlay, and the processes of `nobody` back in the list.

## Behavior

- `TIME` between `USER` and `CPU%`: the CPU time (user + system) a process has used since it
  started, as `TIME` in `top` and Activity Monitor's "CPU Time". The load columns follow as one
  group, `GPU%` now before `POWER`: PID, NAME, USER, TIME, CPU%, MEM, GPU%, POWER.
- The value is the counter `procs.rs` already samples for CPU%: libproc `rusage` user + system
  time for the user's own processes, `/bin/ps` `time` for the others. No new source or syscall;
  `ProcInfo` gets `cpu_time_ns`.
- Format, 8 cells, right-aligned, cut, as htop's TIME+: `M:SS.hh` under an hour (`0:01.97`,
  `59:59.99`), `H:MM:SS` under a day (`23:59:59`), then days and hours (`2d03h`). Zero is dim.
- Group totals (filter terms) sum the time of their processes.
- Header click and `s` / `S` sort by it, largest first. `s` cycles the load columns as on
  screen, then TIME and the text columns: CPU → MEM → GPU → POWER → TIME → PID → NAME → USER.
- Narrow windows: `TIME` drops first, while NAME would get fewer than 16 cells (before USER);
  below that width the other columns drop at the same widths as before. All 8 columns fit an
  80-column window (NAME gets 21 cells).
- Help: a note `TIME`: CPU time used since the process started.
- Help overlay: in a window too short for it, a scrollbar on its right border beside the rows
  (`↑`, the thumb, `↓`), as in the process list; the corners and the text stay.
- `nobody` (uid 4294967294): `/bin/ps` prints its uid as `-2`, which no longer drops the row;
  the user reads `nobody`.

## Decisions

- Config: `proc_sort` gets the value `"Time"`. Released 0.9 reads it as a bad value and falls
  back only that field (to `Cpu`), the others keep theirs; no other config change.
- No JSON / Prometheus / library API change: `ProcInfo` is CLI-only (`app` feature).
- TIME drops before USER: a narrow window keeps who runs a process over how much CPU it has used.

## Result

`TIME` sits between `USER` and `CPU%`, `GPU%` now precedes `POWER`, and `TIME` matches
`ps -o time=` on an M2 under macOS 27. All 8 columns fit an 80-column window, and TIME drops first
below 71 cells. The help shows a scrollbar in a short window, and `nobody`'s processes (`dhcp6d`)
are back in the list. Production code: +40 lines.
