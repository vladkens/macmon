# Hide unavailable power (roadmap item 12, second PR)

In a macOS VM (no IOReport energy channels, no SMC) every power value reads 0 and the TUI shows a
row of four empty boxes (`CPU 0.00W`, `GPU 0.00W`, `ANE 0.00W`, `Power 0.00W`). This PR has the
library tell a VM and hides what a VM doesn't have. Non-breaking: the `soc` object gains one key,
Prometheus leaves out gauges only in a VM, real hardware is unchanged. Aim ≤ 200 production lines
(`make loc REF=origin/main`), stop and report past it.

## Behavior

- `SocInfo::vm`: sysctl `kern.hv_vmm_present` is 1 (0 or absent on a Mac), read once
  with the SoC info. In a VM power and frequencies read 0, temperatures None, fans are empty.
- JSON: the metrics keep the released shape; the `soc` object (`pipe --soc-info`, `/json`) gains
  `"vm": bool`.
- Prometheus, in a VM only: no `cpu`, `gpu`, `ane`, `all`, `sys`, `ram`, `gpu_ram` `_power_watts`
  and no `ecpu_freq_mhz`, `pcpu_freq_mhz`, `cpu_tier_freq_mhz`, `gpu_freq_mhz`.
- TUI, in a VM: no power row (the CPU / GPU / RAM row takes the whole metrics box), POWER `-` for
  every process from the first process sample, so no "POWER: own processes only" note.

## Decisions

- One VM flag instead of per-source availability: a Mac has every source, a VM none; the flag is
  known before the first sample.
- The flag lives in `SocInfo`, static machine information that `pipe`, `serve` and the TUI all
  have, so `Metrics` and its JSON stay as released.
- The POWER column stays (with `-`), so the column set and a saved POWER sort don't change.
