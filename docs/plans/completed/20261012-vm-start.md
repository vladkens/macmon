# macmon starts without IOReport hardware counters (roadmap item 12, first PR)

macmon doesn't start in a macOS VM (Apple Virtualization / UTM, `VirtualMac2,1`, "Apple M2
(Virtual)", one perflevel "Standard" x4): the SoC info, the IOReport subscription and the TUI
sampler thread each stop it. This PR makes every source optional where it is absent, so the CLI
and the TUI start and show CPU usage, memory and the rest that the VM has. JSON, Prometheus and
the library types stay unchanged. Aim ≤ 200 production lines (`make loc REF=origin/main`), stop
and report past it.

## Behavior

- Absence is detected per source, never by "is a VM"; real hardware takes the same paths as
  before.
- SoC info: one perflevel ("Standard" in a VM) is one CPU tier labeled `_`, the core type
  unknown (the deprecated `ecpu_*` / `pcpu_*` point at it). The deprecated `system_profiler`
  fallback isn't extended: `hw_native` reads the single perflevel.
  Without a `pmgr` / `pmgr-child` node in `AppleARMIODevice` the frequency tables are empty; a
  `pmgr` node without tables still fails with "No CPU frequencies found", so unknown real chips
  stay loud.
- IOReport: when the channel filter selects no channel there is no subscription; any other
  subscription failure still errors. `MACMON_FORCE_CLPC` / `Sampler::with_clpc` still error
  without CLPC channels.
- SMC: `SMC::new` errors when there is no `AppleSMC` service (it returned a dead connection);
  the sampler keeps no SMC then: no SMC temperatures, fans or system power.
- CPU usage without "CPU Stats" channels or without frequency tables comes from
  `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` tick deltas: per core `active_ratio`,
  `scaled_ratio` the same, `freq_mhz` 0; only for a single tier (ticks don't tell a CPU's tier,
  and the M6 lists its CPUs as E, S, P).
- Without the sources, power and frequencies read 0, temperatures null and fans empty (hiding the
  power row is the next PR).
- TUI: no `unwrap` on the sampler path; a sampler error ends the TUI with the error after the
  terminal is restored. With one CPU tier its box reads `CPU 63%` and the chip title `4CPU`; a
  frequency of 0 shows no `@ 0 MHz`.
- `macmon debug` prints an error for a failing section and goes on with the next one.

## Decisions

- `IOReport::with_filter` (crate-private) returns `Option`; the public `IOReport::new` keeps its
  signature and errors on an empty selection.
- `SMC::open` (crate-private) returns `None` without the service, so an `IOServiceOpen` failure on
  real hardware still errors.
- Ticks are `u32` counters that wrap: deltas use `wrapping_sub`.

## Result

+170 production lines. In review the single tier became `_`, the core type unknown (a letter
could collide with a future Apple core type), the `system_profiler` change was dropped, the tick fallback was limited to a single tier (the M6 lists its
CPUs as E, S, P), the first tick baseline moved into `get_metrics`, and a `GPUPH` channel without
a GPU table is skipped. Hiding the unavailable power is the next PR.
