# Hide unavailable power (roadmap item 12, second PR)

In a macOS VM (no IOReport energy channels, no SMC) every power value reads 0 and the TUI shows a
row of four empty boxes (`CPU 0.00W`, `GPU 0.00W`, `ANE 0.00W`, `Power 0.00W`). This PR has the
library tell which sources are available and hides what is not. Non-breaking: JSON gains one key,
Prometheus leaves out gauges only where the source is missing, real hardware is unchanged. Aim ≤ 200
production lines (`make loc REF=origin/feat/vm-start`), stop and report past it.

## Behavior

- `Metrics::available` (`Availability`): `power` (CPU / GPU / ANE power: an `Energy Model`, `CLPC`
  or `PMP` channel subscribed), `sys_power` (SMC `PSTR` read this sample), `cpu_freq` (`CPU Stats`
  channels and a frequency table for every tier), `gpu_freq` (`GPU Stats` channels and a GPU
  table). Detected per source, never by "is a VM". `Availability::default()` is all true, so
  hand-built `Metrics` keep their meaning.
- JSON (`pipe`, `/json`): one more key, `"available": {"power": true, "sys_power": true,
  "cpu_freq": true, "gpu_freq": true}`; every other key keeps its value.
- Prometheus: without `power` no `cpu_power_watts`, `gpu_power_watts`, `ane_power_watts`,
  `all_power_watts`, `ram_power_watts`, `gpu_ram_power_watts`; without `sys_power` no
  `sys_power_watts`; without `cpu_freq` no `ecpu_freq_mhz`, `pcpu_freq_mhz`, `cpu_tier_freq_mhz`;
  without `gpu_freq` no `gpu_freq_mhz`.
- TUI: without `power` and `sys_power` the power row is gone and the CPU / GPU / RAM row takes the
  whole metrics box; the per-process POWER column shows `-` for every process, so the "POWER: own
  processes only" note stays off.

## Decisions

- A public field of `Metrics`, since `pipe`, `serve` and the TUI all get `Metrics`; the struct's
  docs already ask for struct update syntax when built by hand.
- The POWER column stays (with `-`), so the column set and a saved POWER sort don't change.
- Until the first sample the TUI assumes power is available, as before.
